# Свои иконки

[← Документация](../../README.ru.md) · [English](../en/icons.md) · **Русский**

Везде, где Zenith принимает имя иконки — тип контента, трекер дневника, папка, виджет
дашборда, манифест модуля, — подойдёт либо встроенное имя (lucide), либо свой идентификатор
вида `zi:<источник>/<имя>`. Дать своё можно двумя способами.

**Паки иконок.** Положите папку с файлами `.svg` в папку `icons/` внутри плагина:

```
icons/
  acme/
    pack.json     ← необязательно: { "name": "Acme Icons", "author": "Acme Inc" }
    logo.svg      → zi:acme/logo
    mark.svg      → zi:acme/mark
```

Они появляются вверху каждого выбора иконки, над встроенным набором. **Настройки →
Оформление → Паки иконок** показывают, что загрузилось, и — что полезнее — называют каждый
отвергнутый файл и причину. Россыпь файлов вместо манифеста — сознательный выбор: обычный
сценарий здесь это распаковать что-то скачанное.

**Иконки от модуля.** Модуль может принести свой артворк, чтобы логотип стоял рядом с его
переключателем. Положите `icon.svg` рядом с `main.js` и укажите его в манифесте:

```json
{ "id": "my-module", "name": "My Module", "icon": "icon.svg" }
```

Папка `icons/` внутри модуля работает так же (`icons/foo.svg` → `zi:my-module/foo`). Ни то
ни другое не требует кода. Если артворк генерируется, а не поставляется файлом,
`zenith.registerIcon(name, svg)` вернёт идентификатор или `null`, если SVG отвергнут. Всё,
что модуль зарегистрировал, снимается при его удалении.

**Что принимается.** Только SVG — он наследует `currentColor` и остаётся чётким от 11px до
56px, а PNG-логотип не умеет ни того ни другого. Каждый файл очищается перед сохранением:
`<script>`, `<style>`, `<image>`, `<foreignObject>` и ссылки отвергаются сразу (с указанием
виновного элемента), обработчики `on*` и внешние `href` вырезаются, а внутренние `id` каждой
иконки уводятся в своё пространство имён, чтобы два логотипа не подрались за общий
`<linearGradient id="a">`. Размер файла ограничен 64 КБ.

Учтите: эта очистка — не защита от враждебного *модуля*. Код модуля выполняется через
`new Function` и уже имеет доступ ко всему приложению, ровно как любой плагин Obsidian.
Очистка нужна для паков иконок, а это просто файлы, скопированные пользователем.
