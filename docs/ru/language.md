# Язык

[← Документация](../../README.ru.md) · [English](../en/language.md) · **Русский**

Интерфейс Zenith следует **Настройкам → Основные → Язык** (`Автоматически` идёт за
Obsidian). Английский и русский лежат в `src/core/i18n.ts`; существительные со счётом
проходят через помощник множественного числа, поэтому русский получает свои формы
один/два/пять, а не число, приклеенное к единственному.

## Модули приносят свои строки

Имя и описание модуля живут не в общем словаре плагина: модуль приносит свой кусок словаря,
и каждый список модулей сначала ищет два ключа, а уже потом откатывается на непереведённый
текст манифеста:

```
module.<id>.name
module.<id>.desc
```

Встроенные модули объявляют их в `src/modules/<id>/i18n.ts` и возвращают из
`getTranslations()`. Сторонний модуль делает ровно то же самое — механизм один, поэтому он
не может сгнить на том пути, которым ходят только чужие:

```ts
getTranslations() {
    return {
        en: { 'module.my-module.name': 'My Module', 'my-module.greeting': 'Hello' },
        ru: { 'module.my-module.name': 'Мой модуль', 'my-module.greeting': 'Привет' },
    };
}
```

Ключи обязаны лежать в собственном пространстве имён модуля (`<id>.…` или
`module.<id>.…`); всё остальное отбрасывается с предупреждением. Модуль, способный
переопределить `settings.title`, мог бы переопределить и фразу, которая предупреждает вас
об этом модуле.

Строки можно положить и прямо в `manifest.json` — для имени и описания это место лучше:
список настроек показывает модули, которые **выключены** и чей код никогда не запускался, а
читаете вы там ровно то, по чему принимаете решение:

```json
{
  "id": "my-module",
  "name": "My Module",
  "translations": {
    "ru": { "module.my-module.name": "Мой модуль", "module.my-module.desc": "Делает всякое." }
  }
}
```

Оба канала хранятся отдельно, поэтому загрузка модуля не выбрасывает то, что уже сказал его
манифест, а выгрузка оставляет его строку в списке названной. Для строк, которые
генерируются, а не поставляются файлом, есть `zenith.registerTranslations(table)` — снимается
при выгрузке, как и всё прочее, что регистрирует модуль.

Порядок поиска: собственная строка Zenith для этой локали, затем принесённая модулем, затем
английская у каждого по очереди. Модуль не может забрать ключ, на который Zenith уже
отвечает на этом языке, но *может* дать русский для того, у которого у Zenith есть только
английский.
