# Zenith — план разработки

Составлен 23 сентября 2026 по итогам ресёрча рынка и спора агентов
([отчёт «Горизонт Zenith»](https://claude.ai/artifact/5FEPKSPUtfXx8yLL6WxfC8)) и решения автора,
что оставить. Файл рассчитан на то, чтобы новый сеанс прочитал его и начал с нужного этапа.

**Как пользоваться.** Этапы идут в порядке зависимостей: этап 0 — фундамент, на который
опирается всё остальное. Этапы 2 и 3 независимы и могут идти параллельно. Отмечайте
`[x]` по мере готовности. Одна ветка и один PR на этап (как было с `audit-*`).

## Правила для каждой задачи (Definition of Done)

- [ ] **Зарегистрирована в реестре функций** (этап 0.2): свой `featureId`, модуль,
      значение по умолчанию для каждого шаблона-профиля. Выключенная функция не рисует

- [ ] **Настройки** описаны в схеме модуля (`settings.schema.ts` / `src/settings/schema`)

      «не записано» ≠ «провал».
- [ ] **Телефон**: у всего, что работает на наведении или перетаскивании, есть касательная
      альтернатива.
- [ ] **Тесты** vitest на чистую логику; `npm run typecheck && npm run lint && npm test`.
- [ ] Комментарии в коде объясняют «почему» — как во всём остальном репозитории.

## Этап 0. Фундамент

### 0.1 Строка задачи без потерь — баг, потеря данных

Почти каждая новая функция пишет строки задач (ввод естественным языком, перетаскивание
по сетке, ритуалы, напоминания «выполнено»). Сейчас это опасно:

- `➕ дата` (дата создания из плагина Tasks) стирается при любой правке:
  `ALL_MARKERS_RE` в `src/modules/tasks/services/taskFormat.ts` вырезает её из заголовка,
  поля для неё нет, а `updateLineExtras` / `updateTaskInFile` в `taskWriter.ts` собирают
  строку заново.
- `🔁 every week 🏁 delete` не продлевается: `RECUR_RE` не останавливается на 🆔, ⛔, 🏁.
- Приоритеты 🔺 и ⏬ не распознаются.

Задачи:
- [x] Одна таблица маркеров, из которой строятся все регулярки (сейчас набор символов
      переписан вручную в двух местах — отсюда баг с `RECUR_RE`).
- [x] Неизвестные маркеры (➕ 🆔 ⛔ 🏁 и любые другие) сохраняются в исходном порядке.
- [x] Правка накладывает изменённые поля на разобранную строку, а не собирает её с нуля.
- [x] 🔺/⏬ читаются как крайние уровни для сортировки, значок на диске остаётся, пока
      пользователь сам не сменит приоритет. Тип `Priority` не расширять.
- [x] Новое повторение не копирует 🆔; `🏁 delete` удаляет выполненную строку.
- [x] Тесты (`tests/taskFormat.test.ts`, `tests/taskWriterGuards.test.ts`): строки из
      документации Tasks проходят разбор и сборку байт в байт; правка заголовка сохраняет
      ➕ и 🆔; повтор с 🏁 продлевается; 🔺 переживает правку.

> Сделано в ветке `foundation`. Попутно: перенос задачи в корзину больше не стирает ⏰/⏱/⏲/✅,
> смена статуса в окне правки теперь сохраняется, переименование подзадачи в списке не
> затирает её маркеры, теги читаются по правилам Obsidian (`#работа` — тег, `C#` и `#123` — нет),
> новое повторение не копирует также ⛔ и ссылку на блок (как плагин Tasks), `➕` ставится на сегодня.

### 0.2 Реестр функций (feature flags)

Главная концепция плагина — можно выключить всё, чем не пользуешься. Нужна одна точка правды.

- [x] `src/core/features.ts`: реестр `FeatureDefinition { id, moduleId, labelKey, descKey,
      default, requires?: FeatureId[], settingKey?: keyof ZenithSettings }`.
      `id` в виде `модуль.функция`: `tasks.naturalInput`, `calendar.dragSchedule`…
- [x] Хранение: `settings.features: Record<FeatureId, boolean>` (scope `shared`).
      Уже существующие тумблеры (`weatherShowAir`, `prayerShowSunrise`,
      `journalCaptureTasks`, `dashboardShowDate`…) **не переименовывать** — регистрировать
      в реестре со ссылкой `settingKey`, чтобы профили управляли ими так же.
- [x] API: `isFeatureOn(id)` для кода вне React, `useFeature(id)` — хук с подпиской.
      `requires` учитывается: функция без включённой зависимости считается выключенной,
      а в настройках показано почему.
- [x] В форме настроек каждого модуля — группа «Функции» с тумблерами из реестра, с

- [x] **Аудит существующих функций**: пройти каждый модуль и завести флаг на каждую видимую

## Этап 3. Время намаза: годовая таблица офлайн

Что уже есть: источник по умолчанию — Aladhan (`src/modules/prayer/prayerApi.ts`), месяц за
запрос, запасной вариант — расчёт на устройстве (`prayerSource.ts`, origin
`local | api | fallback`).

**Диагноз поставлен (23.09.2026).** Время расходилось с приложением IslamApp, стабильно.
Сравнение на Ставрополе (45,03° с. ш.) за 23.09:

| | Фаджр | Зухр | Аср | Магриб | Иша |
|---|---|---|---|---|---|
| Zenith (ДУМ РФ 16°/15°, ханафитский аср) | 04:33 | 12:05 | 16:18 | 18:08 | 19:29 |
| IslamApp | 04:21 | 12:04 | 15:27 | 18:08 | 19:41 |
| Движок Zenith: MWL 18°/17°, стандартный аср | 04:21 | 12:05 | 15:27 | 18:08 | 19:41 |

Прогон движка плагина по всем методам: **MWL + стандартный (шафиитский) аср совпадает с
IslamApp до минуты**, кроме зухра (+1 — округление: плагин округляет полдень до ближайшей
минуты, приложение, похоже, отбрасывает секунды). Движок верен; расхождение давали настройки
по умолчанию (`russia` + `hanafi`), а не баг. Подбор углов перебором дал ровно 18°/17°.
IslamApp, по словам автора, сам выбирает мазхаб для асра по местоположению.

Выводы для этапа:
- Функция «Подобрать под моё приложение» доказала смысл — ровно этот подбор, только
  автоматический.
- Метод и мазхаб нельзя молча ставить по умолчанию: при первом включении модуля
  (и в шаблоне «Намаз и пост») спрашивать явно, со ссылкой на подбор.
- Выбор мазхаба — религиозное решение пользователя; плагин предлагает, но не решает.

Слабые места кеша всё равно есть и чинятся на шаге 3: кеш в `localStorage` (свой на каждом
устройстве, может очищаться), месяц грузится лениво (первый кадр — по расчёту), дни
соседнего месяца и офлайн показывают расчёт.

Шаги:

## Этап 9. API модулей v2: сторонние модули меняют встроенные

Сейчас (`src/core/moduleApi.ts`, v1) модуль может только добавлять своё: виджеты, кнопки
навигатора, виды, команды, блоки кода, иконки, переводы. Точек расширения встроенных модулей
нет.

### 9.1 Разрешения
- [ ] В манифесте — `permissions`: `tasks:read`, `tasks:write`, `journal:read`,
      `journal:write`, `content:read`, `content:write`, `calendar:layers`, `ui:slots`,
      `settings:<модуль>`, `network:<хост>`…
- [ ] Окно согласия перечисляет их простыми словами; изменение списка при обновлении —
      повторное согласие.
- [ ] API-фасад отдаёт только разрешённые пространства; вызов без разрешения — понятная
      ошибка.

### 9.2 Точки расширения
- [ ] `tasks`: свои маркеры/поля (работают благодаря 0.1), действия в меню задачи,
      фильтры и сортировки.
- [ ] `journal`: свои виды трекеров, разделы панели дня.
- [ ] `calendar`: слои событий только для чтения — сюда ляжет отложенное чтение ICS как
      сторонний модуль.
- [ ] `content`: `metadataProvider` — вернуть автозаполнение можно будет только так, со
      своим разрешением `network:`.
- [ ] `prayer`: `registerProvider` — провайдер своего муфтията.
- [ ] `ui`: именованные слоты во встроенных видах (`tasks.item.afterTitle`,
      `journal.day.afterTrackers`…) и заменяемые отрисовщики с откатом на встроенный при
      ошибке. Никакого патчинга внутренностей.
- [ ] `settings`: добавить поля в страницу встроенного модуля; `features.register` —
      функции стороннего модуля попадают в профили.
- [ ] События: `task:completed`, `task:created`, `journal:recorded`… (только чтение).
- [ ] Запись во встроенные данные — только через существующие писатели с их защитами
      (`taskWriterGuards`), не напрямую в файлы.

### 9.3 Безопасность
- [ ] Хеш кода: заменить 32-битный FNV-1a (`moduleInstaller.ts`) на SHA-256 (SubtleCrypto) —
      FNV легко подобрать. Можно сделать раньше, отдельным маленьким PR.
- [ ] Журнал действий модуля (что и куда записал) в настройках.
- [ ] Граница ошибок вокруг каждого расширения; автоотключение после повторных сбоев.
- [ ] «Безопасный режим» — запуск без сторонних модулей (команда и настройка).
- [ ] Честно в документации: `new Function` — изоляция, а не песочница
      (`moduleEval.ts` уже это признаёт). Разрешения — договор и помощь при проверке
      кода; настоящая защита — согласие, закреплённый хеш и читаемый исходник.
- [ ] `ZENITH_MODULE_API_VERSION = 2`, модули v1 продолжают работать.
- [ ] Пример-модуль в `modules_def/`, который использует слот и точку расширения.
- [ ] `docs/en/module-api.md` и `docs/ru/module-api.md`.

## Решения автора (23 сентября 2026)

1. **Обложки контента** — оба варианта: файл из хранилища и вставленная ссылка.
   **Поля `externalRating` / `source` / `sourceId`** — поддержку убрать полностью (этап 2).

   (18°/17°) со стандартным асром, Zenith по умолчанию — ДУМ РФ (16°/15°) с ханафитским.
   С MWL движок Zenith совпадает до минуты. Главный шаг этапа 3 — автоматический подбор
   «под моё приложение» и явный выбор метода при первом включении.

4. **«Жизнь в неделях»** — только вручную, ни в одном шаблоне.
5. **Ритуалы** — напоминания в 08:00 и 21:00, по умолчанию выключены.
6. **Шаблоны профилей** — набор из этапа 1 утверждён.
